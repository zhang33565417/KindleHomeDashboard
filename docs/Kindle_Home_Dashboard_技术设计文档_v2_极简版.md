# Kindle Home Dashboard 技术设计文档 V2.0（个人自用极简版）

> 用途：直接交给 ChatGPT Work 开发。日期：2026-10-21。
>
> 目标：先完成手机/电脑可用的管理页面、Java 后端和可下载的 Kindle PNG；**本阶段不开发 Kindle 本机插件、定时唤醒和屏保**。
>
> 原则：一个 JAR、一套静态网页、几个 JSON 文件、一张最新 PNG。能用、好改、能保存数据即可，不按商业系统标准增加工程复杂度。

## 0. 本版与 V1 的差别

**明确删除**：MySQL、MyBatis、Flyway、Docker、Nginx、Spring Security、后台登录、用户与角色、Redis、消息队列、Vue/Vite/Node 构建、Playwright/Chromium、图片历史数据库、复杂任务队列、草稿/发布流程、多用户和多看板管理。

**保留**：日期天气、孕周与预产期倒计时、今日安排、胎动计数、自定义文本/倒计时、模块拖动缩放、可配置分辨率、灰度 PNG、手机管理、天气缓存、文件持久化、后续 Kindle 拉图接口。

**验收路径**：打开页面 → 设置城市/预产期 → 编辑任务/记录胎动 → 调整模块 → 看到真实 PNG 预览 → 下载 `dashboard.png` → 重启服务数据仍在。

### 0.1 最重要的边界

无登录意味着任何能访问服务的人理论上都可以读写数据。**只能部署在可信局域网/本机，绝不能直接映射到公网。** 若需要远程访问，优先通过自己现有的私有 VPN/内网穿透的鉴权通道，不在本项目内自造认证系统。不要在公开日志里打印孕期、胎动、待办详情。

## 1. 简单技术栈

| 部分 | 技术 | 为什么 |
|---|---|---|
| 服务端 | Java 21 + Spring Boot 3.x（Spring Web） | 熟悉，独立运行 |
| JSON 读写 | Spring Boot 自带 Jackson | 无数据库 |
| Web 管理页 | 原生 HTML/CSS/JavaScript | 无 Node / npm / 构建流程 |
| 画布排版 | 轻量拖拽库 GridStack.js 的静态 JS/CSS 文件 | 实现拖动、缩放、排序即可，无需框架 |
| PNG 渲染 | Java2D `Graphics2D` + `ImageIO` | 不需要浏览器截图、Chromium |
| 天气 | JDK `HttpClient` + Open-Meteo API | 使用经纬度取实时天气 |
| 数据 | 本地 JSON + 本地 `dashboard.png` | 看得见、方便手动备份 |
| 更新 | `@Scheduled` + 保存后的即时重渲染 | 够用即可 |
| 启动 | `java -jar ...jar` | 一个进程，直接部署 |

依赖控制在 `spring-boot-starter-web`、`spring-boot-starter-test`（可选的简单测试）等基础组件；可加必要的小依赖，但避免为简单功能引入大框架。拖拽库脚本置于 `static/vendor`，页面直接引用，无前端编译。

**重要实现选择**：管理页中的“最终效果预览”直接使用服务端生成的 PNG。管理页可在编辑时叠加可拖拽矩形辅助线，但不需要另造一套与 Java2D 完全一致的 HTML 看板模板。拖动完成、修改属性后调用后端预览即可。这样最终呈现以 PNG 为准。

## 2. V1 功能范围（一次做完最小闭环）

### 2.1 页面

采用一个页面 `index.html` + 页内导航即可，不要完整的 SPA 路由系统。

1. **看板首页**：当前 PNG 预览、最后生成时间、立即生成、下载 PNG、当前天气更新时间。
2. **内容管理**（可以做成侧边栏或分组标签）：
   - 位置/天气：城市名称、纬度经度（可先手填；无需开发城市自动搜索）、手动刷新天气。
   - 孕期：预产期日期，自动计算孕周和出生倒计时，未设置显示“待设置”。
   - 今日安排：添加、编辑、完成、删除；日期选择，默认当天；排序可用上移/下移替代复杂拖拽。
   - 胎动记录：开始一段计数、点一次“记一次”、撤销最近一次、结束计数、查看当天会话和记录时间；可以填备注。
   - 自定义信息：编辑文本卡片标题和内容；支持一条自定义倒计时（名称 + 日期）。
3. **布局编辑**：桌面浏览器可拖动/缩放 12 列网格模块，控制显示/隐藏，修改标题、字号、对齐、边距；手机端最低要求支持显示/隐藏与顺序/属性调整，不强求流畅手指拖拽。
4. **简单设置**：图片宽高、时区、天气经纬度、刷新间隔；使用默认值即可开始体验。

### 2.2 内置模块

| type | 内容 | 配置重点 |
|---|---|---|
| `DATE` | 年月日、星期 | 显示格式、字号 |
| `TIME` | 图片生成时间（非实时秒表） | 显示/隐藏 |
| `WEATHER` | 城市、气温、天气、最高最低温 | 显示项 |
| `GESTATION` | 孕周 `X周Y天` | 展示标题 |
| `BABY_COUNTDOWN` | 距预产期天数 | 标题、字号 |
| `TODOS` | 今日安排列表 | 显示条数 |
| `MOVEMENT` | 当天胎动计数/最近会话信息 | 展示模式 |
| `TEXT` | 自定义标题与内容 | 自由文字、多行 |
| `COUNTDOWN` | 自定义日期倒计时 | 名称、目标日期 |

同一类型模块允许添加多个，`TEXT` 特别适合任意内容。MVP 不需要上传图片、RSS、复杂日历表格、AI 生成内容等。

### 2.3 不做

不开发用户注册、登录、权限、审计、账户体系、配色主题市场、动态插件执行、多人同时编辑、复杂历史报表、医用胎动预警或医学评价、通知推送、Kindle 本机安装/升级/联网/休眠功能。

## 4. 文件数据模型与实例

### 4.1 `settings.json`

```json
{
  "title": "家庭信息看板",
  "timezone": "Asia/Shanghai",
  "canvasWidth": 1072,
  "canvasHeight": 1448,
  "weather": {
    "cityName": "郑州",
    "latitude": 34.7466,
    "longitude": 113.6254,
    "refreshMinutes": 60
  },
  "dueDate": null,
  "defaultRenderMinutes": 60
}
```

**注意**：1072×1448 仅是开发示例，不能认定与你的 Kindle 真实分辨率一致。页面可修改宽高，限制合理范围（比如 400–3000 像素）并保持原比例预览。城市坐标是演示默认值，可修改。预产期绝不能用演示日期冒充用户真实数据。

### 4.2 `layout.json`

采用 12 列 × 24 行逻辑网格。每个模块拥有 `id/type/enabled/x/y/w/h/props/style`。布局坐标按整数保存，保持界内、无重叠；模块类型可枚举控制。

```json
{
  "columns": 12,
  "rows": 24,
  "background": "#FFFFFF",
  "widgets": [
    {
      "id": "date-1", "type": "DATE", "enabled": true,
      "x": 0, "y": 0, "w": 7, "h": 3,
      "props": { "showWeekday": true },
      "style": { "fontSize": 42, "textAlign": "left", "padding": 12 }
    },
    {
      "id": "weather-1", "type": "WEATHER", "enabled": true,
      "x": 7, "y": 0, "w": 5, "h": 3,
      "props": { "showHighLow": true },
      "style": { "fontSize": 26, "textAlign": "right", "padding": 12 }
    },
    {
      "id": "movement-1", "type": "MOVEMENT", "enabled": true,
      "x": 0, "y": 9, "w": 6, "h": 4,
      "props": { "title": "今日胎动" },
      "style": { "fontSize": 28, "textAlign": "left", "padding": 14 }
    },
    {
      "id": "todo-1", "type": "TODOS", "enabled": true,
      "x": 0, "y": 14, "w": 12, "h": 7,
      "props": { "limit": 5 },
      "style": { "fontSize": 24, "textAlign": "left", "padding": 12 }
    }
  ]
}
```

默认应生成一份**完整、美观且可编辑**的预设布局，包含 DATE、WEATHER、GESTATION、BABY_COUNTDOWN、MOVEMENT、TODOS、TEXT；上面的 JSON 只是格式示意。

### 4.3 `todos.json`

```json
[
  {
    "id": "t-uuid",
    "date": "2026-10-21",
    "content": "阅读半小时",
    "done": false,
    "sort": 10
  }
]
```

只展示当前看板日期对应任务；可新增、编辑、删除、完成/取消完成。无任务时显示“今日暂无安排”。字符串限制长度，超长文本截断或按行数裁切。

### 4.4 `movements.json`

```json
{
  "sessions": [
    {
      "id": "session-uuid",
      "startedAt": "2026-10-21T09:00:00+08:00",
      "endedAt": null,
      "note": "",
      "taps": [
        { "id": "tap-uuid", "at": "2026-10-21T09:05:00+08:00" }
      ]
    }
  ]
}
```

- 点击“开始计数”：新增会话（已存在进行中的会话则直接继续，不重复创建）。
- 点击“记一次”：在当前会话追加一次事件。展示当次计数与今日计数。
- 点击“撤销上一次”：只撤销当前会话最后一条事件，需可见的确认/恢复提示即可。
- 点击“结束计数”：设置 `endedAt`；已结束会话可以查看，不继续追加。
- 会话归属哪一天以所配置时区为准；按记录时间归属当天，跨午夜不要重复计算。
- 点击要防重复提交（按钮短暂禁用/请求 UUID 去重），但不必设计复杂幂等中间件。
- 胎动计数**仅记录用户手动输入**，不做正常/异常判断。计数方式如果有医生个性化指导，以医生意见为准。

### 4.5 `weather.json`

保存 `lastSuccessAt`、城市经纬度、温度、天气码、最高最低温、湿度、状态。接口失败时保留上一次成功的数据并清晰显示“上次更新于 XX”；首次失败显示“天气暂不可用”，不要生成虚假的晴天或气温。

## 5. 时间与计算规则

### 日期和时间

- 服务器计算使用配置的 IANA 时区，例如 `Asia/Shanghai`；不要默认使用服务器所在时区。
- PNG 显示的是生成时刻。若需要每分钟变化，必须重新生成图片；此版本默认不提供秒级刷新。
- 每隔几分钟简单检查是否跨日，跨日后重新生成 PNG，确保日期、今日安排和孕周自动更新。

### 孕周

- 用户只输入**预产期**，采用 40 周（280 天）作为常见估算前提：`预计孕期起点 = 预产期 - 280 天`。
- `已过天数 = 今天 - 预计孕期起点`，孕周 = `已过天数 / 7`，余天 = `% 7`。倒计时 = `预产期 - 今天` 的自然日天数。
- 未输入预产期：显示“待设置”；预产期已过：显示“距预产期已过 X 天”或使用适当的文本提示，不能显示负的剩余天数。
- 只是用于家庭信息展示的日期估算，不输出医学判断。

### 天气

- 通过 Open-Meteo 天气 API 使用经纬度查询（例如 `current=temperature_2m,relative_humidity_2m,weather_code`，`daily=temperature_2m_max,temperature_2m_min`）。
- 服务启动时读取缓存；缓存不存在或超期时再请求。请求超时建议 5～10 秒，失败不导致整个页面崩溃。
- 默认约 60 分钟更新一次，允许手动刷新；天气变化后重新生成 PNG。遵守天气服务的使用条款及必要署名。

## 6. 最小 REST API

统一返回 JSON，失败时返回明确提示。不需要专门做通用返回封装、全局错误码大体系或 Swagger 门户。

| Method | URL | 作用 |
|---|---|---|
| GET | `/api/state` | 首页所需聚合数据：设置、计算后的孕周、天气、当天任务、当天胎动汇总、图片时间 |
| GET | `/api/settings` | 获取设置 |
| PUT | `/api/settings` | 更新设置（预产期、像素、天气位置、时区），保存并重绘 |
| GET | `/api/layout` | 获取布局 JSON |
| PUT | `/api/layout` | 更新布局（含增删改模块），保存并重绘 |
| GET | `/api/todos?date=YYYY-MM-DD` | 获取指定日期安排 |
| POST | `/api/todos` | 新增安排 |
| PUT | `/api/todos/{id}` | 修改标题、日期、完成状态、排序 |
| DELETE | `/api/todos/{id}` | 删除安排 |
| GET | `/api/movements?date=YYYY-MM-DD` | 获取当天会话/记录/汇总 |
| POST | `/api/movements/start` | 开始计数会话 |
| POST | `/api/movements/{id}/tap` | 记一次胎动 |
| POST | `/api/movements/{id}/undo` | 撤销最后一次 |
| POST | `/api/movements/{id}/end` | 结束会话 |
| PUT | `/api/movements/{id}/note` | 修改备注 |
| GET | `/api/weather` | 最近成功的天气与更新时间 |
| POST | `/api/weather/refresh` | 立即刷新天气；网络失败返回提示及旧缓存 |
| POST | `/api/render` | 立即重新生成 PNG；返回生成时间 |
| GET | `/api/image` | 获取当前 PNG，用于预览及未来 Kindle 拉取 |
| GET | `/api/health` | 返回 `{"ok":true}` |

图片接口可返回 `Content-Type: image/png` 和 `Cache-Control: no-cache`，可选 ETag。前端需要在每次重绘后给 URL 添加 `?v=时间戳`，避免浏览器继续显示旧图。不要为 ETag/设备 Token 设计过度复杂的协议。

请求校验只做基本防错：空标题、过长文本、非法日期、分辨率不合理、未知模块、画布越界、坐标重叠、错误经纬度等应返回 400；服务端禁止任意文件路径输入，避免路径穿越。

## 7. PNG 渲染（核心功能）

### 7.1 为什么采用 Java2D

Web 管理页面负责输入和布局编辑；后端将 JSON 数据与动态值绘制成 `BufferedImage`，再通过 `ImageIO.write` 写入 PNG。这样无需 Playwright、Chromium 和复杂字体/浏览器部署环境。

**代价**：不支持网页 CSS 的完整排版能力。但家庭信息看板只需要字体、方框、分割线、图标（可用简单线条）、文字自动换行等，Java2D 足够实现初版。

### 7.2 绘制要求

1. 根据 `canvasWidth/Height` 创建白底图片，推荐 `TYPE_BYTE_GRAY`；开启文字抗锯齿。保留黑、深灰、浅灰、白的层级。
2. 按逻辑网格计算像素矩形：`pxX = x / columns * width`，`pxW = w / columns * width`；Y 轴同理（注意整数取整边界）。
3. 每个模块独立绘制背景/分隔线、标题、内容，按模块矩形 `clip`；确保不会画出边界。
4. 显示模块状态：数据缺失时绘制“待设置/暂无数据”；天气失败绘制缓存及时间，不能抛异常致整个页面白屏。
5. 适配中文字体：优先加载可用的中文字体（如系统安装的 Noto Sans CJK），启动时检查字体；若无中文字体，README 说明如何在运行环境安装或配置字体路径。避免把未经授权的商用字体打包到仓库。
6. 基础文字排版：自动换行、最大行数、裁切、省略号；长任务或长便签不能影响其他模块。
7. 所有模块使用同一份布局配置；前端以 `GET /api/image` 展示最终输出，图片才是画面真实来源。
8. 将生成结果先写 `dashboard.tmp.png`，成功后替换 `dashboard.png`；失败保留上一次成功生成的图片，记录简要错误。
9. 在生成后显示图片像素大小、生成时间和实际预览；提供“下载 PNG”。

### 7.3 自定义布局操作

- 初版有默认预设，用户能看到成品，不需要从零配置。
- 电脑端拖动、改变宽高、编辑字号/标题/边距，支持添加 `TEXT`、`COUNTDOWN` 等模块和删除多余模块。
- GridStack 只负责操作 `x/y/w/h`，其他数据使用侧边表单；点击“保存并生成”完成更新。
- **移动端可只编辑内容和模块参数**；复杂自由拖拽只要求桌面可用，缩小工作量。
- 每次修改触发预览不要求毫秒级实时，保存后 1～3 秒内通常能拿到新图片即可，具体视设备性能；不要做复杂任务队列。

## 8. 自动更新与同步策略

MVP 不需要消息总线。

- 任何内容变化（任务、胎动、布局、预产期）→ 保存 JSON → 请求一次重绘。
- 手动点击刷新天气 → 请求天气 → 成功更新缓存 → 重绘。
- 后台每隔约 60 分钟刷新天气；每隔约 5 分钟检查跨日，跨日后重绘。
- 渲染操作用一个同步锁避免同时写入 PNG，多次更新时顺序执行即可；无需 Redis、异步队列、WebSocket。
- 如果数据未变，是否跳过重绘属于优化项，不阻塞 V1。
- `GET /api/image` 始终返回最新成功图片；启动时若没有图片则立即生成一张默认看板。

## 9. 运行方式

建议 `application.yml`：

```yaml
server:
  port: ${SERVER_PORT:8080}
  address: ${SERVER_ADDRESS:127.0.0.1}

board:
  data-dir: ${BOARD_DATA_DIR:./data}
```

**电脑本机访问**：

```bash
mvn spring-boot:run
# 或打包
mvn clean package
java -jar target/kindle-home-dashboard-*.jar
# 打开 http://127.0.0.1:8080
```

**想在家庭手机上打开**：仅在可信局域网内将 `SERVER_ADDRESS=0.0.0.0`，并用系统防火墙允许家庭网段访问端口，手机浏览 `http://电脑局域网IP:8080`。请勿做公网端口映射。生产运行可直接用 JAR、`nohup` 或系统服务管理，**不要求 Docker**。

数据迁移/备份：关闭服务后将整个 `data/` 目录复制到其他位置即可；恢复时替换该目录。不要将含个人信息的 `data/` 提交到公开 Git 仓库。
